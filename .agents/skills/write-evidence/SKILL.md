# 从证据组织论文

先运行 `python -m paper_composer report 项目目录` 并读完整台账，再用 [叙事证据模板](../../../templates/narrative-evidence.md) 建立论断映射。报告通过只说明已登记材料满足机械条件，不代表科学结论成立或期刊会接收。

按“具体问题 → 组合理由 → 方法与来源 → 实验证据 → 适用边界”组织内容。把读者最关心的改进讲清楚，避免用宏大的首次、新范式或通用最优措辞包装普通组合。

- 机制事实引用原始论文并给定位；本工作的适配与组合增量单独说明。名称变化不构成新机制。
- 开发结果可支撑选择与明确标注为开发集的消融观察，可写入正文机制讨论；最终测试结果用于独立保留集上的效果表述。文献报告的分数和本项目实测分数分列。MVP 的 claims.json 只登记需要最终测试支撑的实验主张；更完整的来源、设计和开发观察放入叙事工作表。
- 每条定量论断关联可比的 baseline／组合运行、split、seed、指标和配置。多个 seed 的均值与离散程度须按真实重复计算；不凭单次运行声称显著性。
- 提升不成立时缩小或撤回对应论断，保留成本、适用场景、失败例等仍被证据支持的发现。不删除负结果来维持故事。
- synthetic、无结果或仅开发结果时交付计划／待填稿，明确待完成实验。不得补造表格、显著性、引用或结论。

最后检查标题、摘要、贡献列表和结论是否超出证据；确认分区体系与期刊要求来自 brief。输出草稿、论断证据映射及少量决定下一步的证据缺口，不承诺录用。
