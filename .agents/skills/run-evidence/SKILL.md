# 在预算内积累可比较证据

读取主候选、[总控](../../../program.md) 和 [实验计划模板](../../../templates/experiment-plan.md)。先用 `python -m paper_composer --help` 确认当前 CLI。CLI 是协议与台账工具，训练由用户的脚本或外部执行器完成。

1. 明确强基线版本、数据划分标识、固定评价器、主指标方向、seed、每次运行估计和预算。先复现基线，再判断组合是否值得继续。
2. 生成两项机制的四组或三项机制的八组全因子消融。公平性应包含相同数据、评价流程、可比训练预算；不能把训练更久的收益全部归因于模块。
3. 写出开发集选择规则、最小改善、最大尝试次数、失败重试上限和简化条件。冻结前 pilot／历史 CSV 单独保留探索台账与原始材料，不补造协议 hash；其实际成本计入 brief.budget 的 prior_gpu_hours 和 prior_runs。完整计划通过校验后冻结。冻结后如需修改，保留旧协议与结果，建立明确的新版本。
4. 冻结后的每次运行立即登记成功、失败或崩溃，以及实际成本。保存配置、seed、split、代码版本、原始日志、artifact 哈希和协议 hash。失败运行的指标为 null，不编造零分；负结果保留实际指标和解释。
5. 按冻结规则使用开发结果固定选择，使用 `select` 完成测试解锁。测试只评价已固定的方法与预定比较组；不得用测试集重新选择模块、阈值或 seed。
6. 累计检查预算。实际超预算仍如实入账，并停止安排下一次运行。先分析失败类型，再决定是否使用预留重试；不以无限调参挽救叙事。

`synthetic` 项目只验证流程，永远不能作为真实论文证据。CLI 只能检查记录一致性，不能确认日志真实性或替代独立复现。结束时交付完整运行台账、预算余量／超支、触发的停止条件、缺失证据和下一项必要实验。
