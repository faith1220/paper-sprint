# 组合候选工作表

最多三个初始候选，收敛到一个主方案。默认强基线加两项机制；第三项应解决独立残余问题。

| 项目 | 填写内容 |
| --- | --- |
| Candidate ID | 与 `candidates.json` 一致 |
| 强基线 | 来源论文、版本、强在哪里、可复现条件 |
| 问题中的失败模式 | 具体样本／条件／错误，不泛写“效果不好” |
| 机制 1 | 来源 Paper ID、原文定位、解决哪个瓶颈 |
| 机制 2 | 来源 Paper ID、原文定位、与机制 1 为何互补 |
| 可选机制 3 | 残余问题、必要性、额外成本 |
| 数据流 | 基线哪个输出接哪个模块，如何回到预测／损失 |
| 适配规则 | 与来源机制相比实际修改了什么 |
| 可证伪假设 | 什么实验结果会支持／推翻互补解释 |
| 最近邻 | 题目、来源、相同点与真实差别 |
| 成本 | 参数、显存、训练和推理成本的估计及依据 |
| 风险 | 接口、监督、数据条件、复现与许可问题 |
| 简化路线 | 去掉哪项机制、保留哪个可验证问题 |
