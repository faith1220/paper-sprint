# 实验协议工作表

决定同步到 `plan.json` 和 brief。先运行强基线，再在固定条件下做完整消融。

## 冻结项

| 内容 | 预先填写 |
| --- | --- |
| 代码与评价器 | commit／快照、指标计算位置 |
| 数据划分 | train／dev／test 清单、hash、划分单位 |
| 主指标 | 名称、方向、单位、次要指标用途 |
| 基线复现检查 | 可比参考值、容差、参考上下文 |
| Seed | 固定列表；重复数与预算相称 |
| 公平比较 | 预处理、backbone、训练预算、调参预算、评价协议 |
| 开发选型 | 选择规则、成本约束、平分时处理 |
| 最终测试 | 基线与已选方案；选择固定后运行 |
| 单次成本 | 预估 GPU 小时及估计依据 |
| 总预算 | GPU 小时、最多运行数、已有开发成本、失败预留 |
| 停止条件 | 失败上限、最低改善、预算不足等 |
| 简化条件 | 哪个观察会触发去掉模块或缩小问题 |

## 两项机制：四组

| Arm | 机制 1 | 机制 2 | 用途 |
| --- | --- | --- | --- |
| baseline | 关 | 关 | 强基线 |
| m1 | 开 | 关 | 机制 1 独立贡献 |
| m2 | 关 | 开 | 机制 2 独立贡献 |
| m1+m2 | 开 | 开 | 组合效果与互补假设 |

三项机制用 CLI 生成八组，不只运行最终组合。开发成本至少按组数 × seed 数估算，再加最终基线／已选方案测试与故障余量；避免把完成不了的矩阵写进协议。

开发集消融可在正文中用于机制解释，但明确标注其开发用途；最终保留集的基线／选定方案比较独立说明。若要在最终测试集主张每项模块的泛化贡献，需另行预定相应验证，不能将开发矩阵改名为最终测试。

## 每次运行台账

用 `record` 追加已发生运行。记录 run ID、arm、seed、split、配置、代码版本、原始日志、hash、指标、成本、正／负／中性／失败结果及说明。失败不补零分；超预算不删除。

冻结前探索另外保留原始台账，将已发生的总 GPU 小时和运行数写入 `brief.budget.prior_gpu_hours` 与 `prior_runs`，不补造历史协议 hash。

协议变更记录：原因、旧 hash、新项目位置、已经接触的数据与测试结果、旧运行去向。所有旧记录保留可追溯。
